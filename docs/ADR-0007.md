# ADR-0007: Sentinel Consumer for Fleet Audit

**Status:** Accepted  
**Date:** 2026-09-07  
**Issue:** [ASP-566](https://linear.app/absolution/issue/ASP-566)  
**Parent:** ASP-563 Weekly Architecture Review  

## Context

Edge RRM nodes produce a hash-chained audit log (BEL-191, `AuditLog` in
`aspen_edge.audit`).  The dashboard/sentinel surface needs a way to observe
these events in real time and provide a read-only, queryable audit trail.

Separately, the fleet ops-manager publishes aggregated status
(`aspen.fleet.ops.status`); a future `fleet.overview` subject will replace
ad-hoc status with a structured overview.

Constraints:
- Flash-only: the consumer must never write to production stores or require
  broad credentials.  Gatekeeper-aware (no publish side effects).
- Local-first: the consumer must work offline with a stub fallback during
  freeze periods.
- Minimal coupling: the consumer is a pure observer — it subscribes, stores,
  and serves; it never publishes or acknowledges.

## Decision

Introduce two new NATS subjects under the `aspen.sentinel.*` namespace:

| Subject | Payload | Producer |
|---|---|---|
| `aspen.sentinel.audit.event` | `{event, node_id, severity, payload}` | `bridge_audit_to_sentinel()` callback |
| `aspen.sentinel.fleet.overview` | `{nodes, degraded, count, ...}` | ops-manager (planned) |

The `SentinelConsumer` dataclass:
- Subscribes to both subjects on instantiation (via `start()`)
- Maintains an in-memory ring buffer (default cap 10k events)
- Optionally persists to a local JSONL file (`persist_path`, flash-friendly)
- Exposes query methods: `tail(n)`, `by_type(event)`, `search(query)`,
  `by_time(start, end)`, `count()`
- Is a pure observer — no publish or acknowledge side effects

The `bridge_audit_to_sentinel()` function bridges local EdgeRRM audit records
onto `aspen.sentinel.audit.event`, decoupling the audit log format from the
sentinel subject contract.

## Consequences

- **Positive:** Dashboard can now display a live audit trail without
  credentials or write access to edge nodes.
- **Positive:** The sentinel is a lightweight, local-first consumer that works
  offline (in-memory buffer) even when NATS is down.
- **Positive:** The overview subject stub is producer-ready — the consumer
  already subscribes.
- **Negative:** No schema enforcement on the wire (JSON envelope with no
  formal validation).  Mitigated by the small surface (two subjects) and
  the `bridge_audit_to_sentinel()` adapter.
- **Negative:** The ring buffer is ephemeral; persistent mode requires an
  explicit `persist_path` and has no log rotation (deferred to a future
  ticket).
